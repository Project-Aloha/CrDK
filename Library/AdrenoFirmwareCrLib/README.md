# A730 firmware format inspection

This is the first portable feature toward the planned full SM8450 Windows GPU driver. `CrAdrenoGmuInspect` returns a checked GMU data/metadata plan and `CrAdrenoSqeInspect` returns the SQE code span and raw/decoded version. The caller supplies an immutable byte copy and retains it throughout inspection. Failed calls leave the complete output unchanged. The parser uses no MMIO, allocation, file lookup, SMC, IRQ or hardware-owner callback.

The fixed first profile is A730/Gen7 using the mainline register/address convention. A GMU wire record contains four little-endian DWORDs (`addr`, `size`, `type`, `value`) followed by `size` bytes. ITCM is `[0,0x4000)`, DTCM `[0x10004000,0x10008000)`, cache `[0x4000,0x1000000)` and uncached `[0x60000000,0x80000000)`. The old DTCM numeric base0x40000 belongs to the Gen7 cache class and never selects a DTCM register view. The Android extended uncached range is outside this constrained profile. Every complete data/preallocation extent must fit one class; data destinations and lengths are DWORD-aligned.

Zero-payload metadata precedes data. Type1 and7 become ordinary/persistent preallocation requirements whose byte count is `value`; types2..6 retain raw core/core-dev/power/power-dev/HFI versions. Repeated equal versions and exact equal preallocation records are retained. Conflicting versions, overlapping data, incompatible overlapping preallocations, unknown zero-size metadata types and metadata after data fail. Nonzero payload records retain `type` and `value` as opaque source data, as the upstream loaders do: the pinned A730 GMU v4.00.07 uses `0xefbeadde` for both. Payload byte count, complete destination range, alignment, overlap and truncation checks remain mandatory. A zero-size DATA record is retained as an ignored record, and an image without payload data fails. These restrictions are an explicit first acceptance subset, not claims that every possible upstream image has these properties. The software bounds are128 records and16MiB input; they are not measured hardware capacities.

The output classifies requirements; it does not prove a destination exists. A future loader must establish exact current TCM views, backed mapped extents for every non-TCM data block, each preallocation requirement and persistence lifetime, then recheck immutable bytes before copying. Mainline's current loader maps named cache/dummy BOs, not the whole uncached class. No compatibility, authenticated firmware, native writer retirement, powered access or valid OS SMMU domain follows from parser success.

SQE has a prefix DWORD followed by nonempty DWORD-aligned code. Both reference loaders omit the prefix from the GPU-read-only code BO. The version is code word0/file word1; a patched low nibble0xa incorporates bits12..23 of code word2/file word3. The prefix is preserved without invented semantics. A730 does not inherit the A630/A650 microcode version admission rule. The parser makes no authentication or security claim. ZAP ELF/MDT validation and real PAS13 loading remain separate work.

The fixed-size GMU output is4160 bytes supplied by the caller; the core validates all records before filling it and avoids a large temporary plan on the kernel/firmware stack. Input may be unaligned. Output must be DWORD-aligned and disjoint from the complete input. Byte copying or mutation by a concurrent caller is outside the immutable-input contract; no borrowed input pointers escape in the plan.
