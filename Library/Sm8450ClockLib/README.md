# SM8450 clock target

The target describes the per-instance clock graph used by native Crane and the permanent Windows PEP clock provider. `Create` clones mutable node ownership; immutable register/rate tables remain shared. Existing users must release their votes before their owner unmaps the controllers.

`Sm8450GpuClock.h` adds the A730 GMU boot profile. Linux `a6xx_gmu_resume` requests GMU200MHz and hub150MHz for A730. The graph holds the existing qualified GPLL0 fixed600MHz vote and its GCC300MHz output gate before selecting GPUCC source6. GMU/FF use HID2 (divide1.5), hub HID3 (divide2), and XO uses source0/HID1 at19.2MHz. Direct source programming refuses a missing output/PLL lease. The target initializer performs no new GPUCC write.

Branch dependencies retain their own explicit input rates, so a200MHz GMU leaf and150MHz hub can share the300MHz GCC parent without conflicting software votes. Read-only divider nodes check the actual low four bits plus one; they never write those registers. For example hub input150MHz and AHB divider2 produce75MHz. The request must equal the rounded-up input/divider rate; an incompatible value fails and unwinds its acquired prefix. Shared acquisition also rejects a changed divider. Cleanup uses the retained ownership, not a newly sampled divider.

Linux's `clk_branch2_aon_ops` has no disable callback. Nodes with that behavior keep the branch enable bit when their last local vote is withdrawn, while releasing their own parent references. Other branches restore their inherited control state. Neither operation proves GPU/GMU DMA has stopped; the execution owner supplies that separate shutdown contract.

The initial graph contains23 GPUCC nodes and five additional GCC nodes. GPUCC binding slots for GX clocks and analogue PLL0/1 remain absent.500MHz GMU, later hub rates and GPU DVFS require the corresponding PLL/power sequencing. CX/GX GDSCs and GPU reset control are not exposed through a guessed generic recipe: mainline GX power-on is delegated to GMU. Power rails, QMP/RPMh/ICB, native/ABL retirement and the actual Windows GPU assignment remain separate integration work. This operating profile is a step toward the complete GPU driver.

The register facts and relationships are drawn from local Linux revision `a53261b60834ce617cc4f3c7723dda8285c59789` ([GPUCC](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/drivers/clk/qcom/gpucc-sm8450.c), [GCC](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/drivers/clk/qcom/gcc-sm8450.c), [branch semantics](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/drivers/clk/qcom/clk-branch.c)) and the workspace's OnePlus Android `gpucc-waipio.c`. Upstream driver notices remain in those reference sources. This table and the bounded ownership implementation are newly written MIT code; upstream programming implementations are not copied.

`Tests/run_sm8450_gpu_clock_tests.py` runs the actual core and target graph in native and NT sanitizer builds. The model checks exact literal clock selectors/dividers, PLL/gate votes, simultaneous consumers, changed divider rejection, AON behavior and failure cleanup. Register completion is controlled by that model; ARM64 compilation and these tests do not establish board clock behavior.
