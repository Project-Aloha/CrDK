# SM8450 DP AUX transport

This library executes native DPCD and I2C-over-AUX FIFO requests and checksum-qualified EDID block reads. It is extracted from the existing `MDSSDpCrDxe/DpAux.c` transport and Linux `drivers/gpu/drm/msm/dp/dp_aux.c`, with the original GPL-2.0-only license and Linux Foundation copyright retained. The native driver remains on its existing implementation until separately reviewed integration.

The caller supplies the actual assigned `0xAE90000/0x200` AHB and `0xAE90200/0x200` AUX views, an immutable callback projection and a stable exclusive DP owner. `Ready` must requalify real hardware, clock/domain, rail/interconnect and shared PHY leases before each callback. It does not accept a caller readiness Boolean or discover/map physical addresses. All requests require caller lifecycle serialization at PASSIVE_LEVEL in Windows; inputs and output buffers must be valid caller-owned storage. An AUX reset also clears HPD interrupts, so the sole DP HPD/controller owner must serialize these operations.

`Init` is metadata-only. `Enable` performs reset, programs timeout/limit registers and verifies the live AUX controls. `Transfer` accepts up to 16 native or 124 I2C bytes, copies write payloads before MMIO, verifies GO-clear and completion FIFO indices, and publishes read output only after the complete successful request. I2C writes retain the bus and reads send STOP, matching the existing native EDID workaround that sends segment/offset before each 16-byte read. `ReadEdid` publishes an entire block only after its checksum passes. `ServiceIrq` issues the DPCD automated-test NAK and vector write; it is not an ISR or parent IRQ handler.

All callbacks require exact completed success. Nonfinal statuses normalize to not-ready. The journal marks uncertain writes before issuing them; failed transactions retain `CleanupPending` and their original owner/IO projection. Timeout retries clear GO and complete a readback-qualified reset before reusing the FIFO. Seven attempts, 25ms per attempt and fixed reset/defer delays bound the operation. A completed timeout returns timeout with no read-buffer publication. A failed reset/control/PHY-clear step requires `Stop` while every prerequisite remains retained.

`Stop` clears GO, completes AUX reset, clears owned interrupt masks and AUX enable/reset controls, and verifies them freshly. It preserves the packed HPD mask and does not acknowledge HPD status. Exact retries keep the same owner. `Uninit` retires only metadata after successful stop or a never-touched initialization, after caller drain. Neither API fences mainlink or DPU scanout DMA, revokes a SMMU mapping, stops USB, or supplies native ownership transfer.

PHY interrupt clearing is deliberately a checked `ClearPhyInterrupts` callback on the actual shared PHY DP owner. Android `dp_catalog.c` uses a separately assigned `dp_phy` view; its v420/v600 implementation selects version-specific status/clear offsets. Those are not generic DP AUX view addresses. The transport never maps that PHY or resets it independently.

`run_mdss_dp_aux_tests.py` links the actual new source with an independent sink/register model in native and NT builds, injects every nominal callback boundary with error and positive nonfinal results, checks retained cleanup and unchanged output, and links the unchanged native AUX source for packet/EDID/retry/delay parity. It separately tests dropped writes, stale completion acknowledgement, foreign HPD preservation and unavailable-provider retirement. `check_mdss_dp_aux_arm64.py` compiles actual EFI and WDK ARM64 objects and links the seven API symbols against the kernel import library. These checks do not prove physical AUX, Windows DP adoption, a new native caller or the shared PHY owner implementation.

Next integration must bind this transport to the sole display/DP resource and PHY owner, with LINK/P0/backing assignment and full native/foreign retirement. Native DP uses DMA1/LM2/PP2, which current Windows WB2 also uses; independent controller IDs do not resolve that conflict. Live DP and WB2 must remain mutually excluded until a real stopped reassignment or another source-qualified slice exists. CPHY/dual DSI/DSC panel qualification is unchanged by this transport.
