# A730 retained HFI transport

This library implements actual shared-memory queue preparation, command publication, response consumption and an ACK-dependent four-command boot exchange. It has no live Windows consumer yet. `BootComplete` means that PERF, BW, CORE_FW_START and START received exact successful ACKs; it does not claim GPU execution, a physical GMU result or permission to release DMA storage.

The selected wire source is Linux `a53261b60834ce617cc4f3c7723dda8285c59789`, `drivers/gpu/drm/msm/adreno/a6xx_hfi.{c,h}`. The A730.1 catalog has no ACD table or IFPC quirk. This first profile rejects nonzero ACD/IFPC requests rather than mixing downstream feature policy into that source. Android Gen7 boot/default DCVS/BCL behavior is a different profile. Firmware blobs are not needed to implement the portable transport; actual activation will select and retain a real compatible GMU image.

The backing is exactly16KiB: a24-byte table header, three48-byte queue headers and three4KiB rings at offsets4096/8192/12288. The source initializer writes table size168 **bytes**, despite the source header's DWORD comment. Queue sizes/indices and message lengths are DWORDs. Modern records are padded to four DWORDs; admission includes the padding in free-space checks. The library validates remote bounds and immutable header fields, tracks its own head/tails and refuses remote command-read progress beyond published data. There is no unchecked `BUG_ON`, loop on firmware response or raw message passthrough. The source-compatible12-bit sequence field is never reused within a context: after4094 commands a new operation is refused.

`Init` does no I/O. Immutable, exact-address IO/backing descriptors and private context must remain resident and unmoved. The backend's synchronous `Execute` pins actual Start/resource/power/memory/translation ownership and invokes one bounded operation; Prepare additionally requires the actual stopped/reset GMU. That authority is an actual owner implementation contract, not a new firmware attestation scheme or caller `Ready` Boolean. DMA acquire/release barriers and a typed HOST2GMU kick execute inside this admitted operation. The owner must provide the appropriate cache visibility for its real mapping; portable CPU ordering alone is insufficient. Interrupt status/clear, OS interrupt/DPC drainage and the monotonic microsecond clock belong to that execution owner. Poll examines shared response/debug queues directly and never waits for an interrupt.

One transaction is retained while waiting for ring space or an ACK. Poll has a bounded message budget and the original absolute deadline; it cannot extend timeout by retrying. Command payload precedes release publication of head, then another release precedes the kick. Errors/nonfinal statuses before or after any callback, malformed responses and deadline expiry permanently close normal progress. A failure after publication preserves that fact and never retries or replays. An ACK consumed before a later provider error is also retained but cannot advance boot or report success. Firmware failures and stale/wrong-ID/wrong-sequence messages are distinguished; debug work is bounded. Empty response/debug queues rearm rx_request with DMA visibility and recheck the producer head after publication, including a response racing that rearm. Input validation errors leave outputs unchanged; admitted operations return retained progress even on failure. Query remains available after seal/fault.

Seal closes software admission and Drain reports whether an accepted operation still exists. Neither calls hardware nor resets the queues. There is no recovery/reinitialize API; failed, sealed or completed backing can be freed/reused only after the actual owner independently proves physical writer stop and mapping retirement. This library neither authenticates firmware nor creates a HAL/SMMU mapping. A GPU CP bank, GMU SID5 domain, PAS13/ZAP and normal GMU slumber have separate ownership contracts.

`Sm8450Hfi.c` serializes the checked AdrenoPower plan and original fixed12-level A730 BW table. CmdDB addresses are supplied in the exact SH0/MC0/ACV/CN0 order, distinct, aligned, nonzero and24-bit. Their provider must qualify resource identity before making the immutable plan; this function cannot infer names from raw addresses. It issues no APSS RPMh vote and does not authorize an OPP or cold-clock transition. It includes AdrenoPower types but calls no AdrenoPower/RPMh implementation. Runtime core imports are only the platform atomic operations; native INF needs SynchronizationLib.

Run `python3 Platforms/CranePkg/Tests/run_adreno_hfi_tests.py --output <fresh-directory>`. Tests link the actual HFI + power code and compile nine unmodified original Linux functions under minimal OS scaffolding, including the original producer/header serializer and queue/BW/perf constructors. They check exact bytes, wrap/padding/full queues, stale/malformed/error ACKs, faults at admitted phases, accepted-ACK-before-provider-error, per-stage boot failure, bounded space/response deadlines, sequence exhaustion, and concurrent Seal/drain. Native/NT DEBUG/RELEASE use ASan/UBSan. Optional ARM64 arguments compile real EFI and WDK objects, with only kit filename-case/WPP accommodations. Receipts archive actual dependency closures. These are modeled-owner tests and cross-compilation, not hardware or a full driver activation result.
