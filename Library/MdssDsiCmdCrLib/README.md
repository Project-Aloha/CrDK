# SM8250 command display core

This portable library supplies the SM8250 DPU6.0, DSI2.4 and DPHY4.1 command backend. `CrMdssCmdInitProfile` captures an immutable provider-selected panel profile by value, including geometry, reset sequence, ON/OFF packets, PHY timings and brightness encoding. The supported compression path is DSC1.1 SCR0 at8bpc/8bpp, with two equal soft slices and one slice per packet. The compatibility `CrMdssCmdInit` and configuration helper retain the original HDK8245 R66451 1080x2340, 60 Hz admission. The shared native frontend must select its actual target profile; the compatibility reference data does not establish panel identity or native resource ownership.

The board identity and command bytes come from the supplied runtime FDT and the [exact stock panel XML](https://github.com/Project-Aloha/UEFIFirmwareBackup/blob/b603f9b535325a7ec6b6562f265aa003202aec21/qcom-hdk8245/BOOT.XF.3.2-00353-SM8250-1/RawFiles/Panel_r66451_fhd_plus_60hz_cmd.xml). The original XML and provenance are retained under `Tests/Fixtures/Hdk8245Panel`. Both the chosen boot argument and primary default-panel phandle select this panel. Generic dual-controller resources and nearby144Hz/CPHY nodes are not the board selection.

Hardware references are Qualcomm Android SM8250 commit `cad09e061ef6cf689a4a1e54d27562e0f042236a` and Linux commit `a53261b60834ce617cc4f3c7723dda8285c59789`. Derived code retains GPL-2.0-only notices. Only pure DSC parameter/PPS functions are reused from the existing DSC library; the SM8250 hardware block has its own legacy register layout.

Both constructors require the exact resource windows and independent retained frame/command DMA mappings. The native owner supplies real clocks, rails, ICB, SMMU, MMIO ownership, board reset and OSKAL interrupt operations. `Ready` must revalidate the current provider incarnation; it is not a dummy success callback. PHY uses PLL offset`0x500` within its`0x7c0` window. Hardware admission remains limited to the qualified nominal lane clock327096544Hz and its exact14 PHY timings; a capability declaration alone does not authorize a new analogue sequence. The rate is quantized by the real18-bit PLL fraction, which the source tests check separately.

The first `Start` accepts a hardware auto-refresh kickoff and returns `NOT_READY`. Release caller serialization to permit IRQ delivery, then retry `Start`. It publishes Active only after real frame completion and fresh native resource/DMA checks. Auto-refresh supports normal framebuffer writes without a CPU redraw loop. `Publish` performs the owner's cache/DMA publication operation. An external deadline may request Stop if no frame arrives; time passing is never a DMA completion proof.

Stop seals and drains native IRQ work, fences DPU fetch through a fresh low/high VBIF acknowledgment, sends panel-off/reset, fences host command DMA, disables DSC, releases external branches, and shuts PHY before panel rails. Any failure retains the remaining resources for Stop-only retry. Native IRQ rundown must not wait under a lock required by callbacks: return `NOT_READY` while retaining ownership, drain outside serialization, then retry. Command-mode EBS preservation needs a genuine SM8250 handoff contract and is not represented by the existing video/SM8450 record.

Validation scripts compile actual sources with native and NT host shims and sanitizers. Host, PHY and DSC tests compile unchanged relevant upstream functions as independent oracles; XML commands and selected FDT timings are parsed independently. Lifecycle tests inject failed callbacks before and after posted effects, including positive non-success statuses. A synthetic720x1280 profile tests actual geometry/PPS/packets/reset/brightness consumption after the caller descriptor is destroyed, pre-effect rejection and the pending first-frame gate. `check_mdss_cmd_arm64.py` also compiles every implementation unit for real EFI and WDK ARM64 headers. These checks do not replace native provider integration, firmware linking or physical display validation.
