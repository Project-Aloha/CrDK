# Audio Pull owner

This portable owner shares the existing graph's permanent AP client port and token allocator. It sends cached circular-buffer MAP and uncached position MAP, configures the actual selected Pull MIID, sets 48 kHz stereo S16/Q15 media format and registers a watermark event. It preserves accepted/unknown command ownership and late-reply identity. Closing the actual graph is a prerequisite for reverse remote UNMAP; each exact UNMAP acknowledgment retires only its own map. Source loss cannot retire remote DMA. The native owner separately retains HAL maps, MDLs and client CPU views.

The exact ACDB graph, codecs, firmware source and installed HAL topology must already be qualified by their real owners. This library performs no allocation or physical mapping, no standalone transport or PIL startup, and does not establish audible output. Watermark events are notifications, never byte-count or wrap-counter substitutes. Position-page reading and a WaveRT client require the native CPU lifetime owner.

Primary source: Qualcomm AudioReach graphservices commit `3094583c726710b66eb0204fc5d6a7b336d9e575`, `gsl/src/gsl_datapath.c` (dual buffers and Pull CFG), `gsl/src/gsl_graph.c` (module event dispatch and registration), `spf/api/modules/sh_mem_pull_push_mode_api.h`, `media_fmt_api_basic.h`, and `spf/api/apm/apm_api.h`. Packet facts use the actual GSL client routing: CFG and registration target the Pull MIID; APM module events decode an 8-byte event header directly after GPR, despite a differing public-header prose comment. No firmware implementation is copied.

This source checkpoint is registered in CRDK and exported to its managed Windows SDK. It is not selected in a native firmware image, and native DMA/View remain unselected by AudioCr. No default HDK profile/calibration or audio endpoint is bundled. Run `python3 Platforms/CranePkg/Tests/run_audio_pull_tests.py --output .tmp/audio-pull-tests` for the portable regression. The synthetic ACDB and controlled remote/OS peer qualify code only; current installed firmware ABI, analog route and audible output still require independent platform evidence.
