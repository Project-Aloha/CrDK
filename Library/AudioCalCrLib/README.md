# AudioCalCrLib

This offline initial-plan compiler consumes one immutable ACDB image and an explicit graph/calibration/codec-DMA profile. It resolves the exact graph, subgraphs, driver properties, module map, inter-subgraph connections, initial calibration and tagged endpoint, then emits owned GPR/APM GRAPH_OPEN and two SET_CFG packets. `Tools/AudioCalPlan` is its executable consumer. No hardware or transport is called.

The complete fixed output owns its bytes. It remains usable after the input image and scratch storage are released. Every non-success result preserves the entire output, input and request; only disposable scratch may change. The caller provides nonoverlapping storage, an immutable readable image and serialization. Read the public header for sizes, alignment and lifetime rules. Policy limits are 32 graph/calibration keys, 64 subgraphs, 512 modules/edges/parameter records, 8192 driver-property bytes and 65536 bytes per complete GPR packet. No large temporary buffers are allocated on a kernel stack.

The supported initial profile is 48 kHz, 16-bit, stereo fixed-point PCM using a single tagged codec-DMA sink. Interface/channel-map values are explicit caller data. The supplied qcm6490 fixture profile is a diagnostic example, not HDK8450 calibration or proof of its physical route. Hardware use additionally requires matching board calibration/PAL/mixer/backend data, compatible firmware/modules, an audio-PD lease, PEP votes, AP-owned SWR/macros/WCD/WSA, muted route configuration and a session that owns command tokens and service/PD/ADSP generations. No data from this helper proves that an APM command succeeded or that graph/DMA ownership has retired.

## Selection and deliberate limits

- GKVT/GKVL rows are bounded and strictly ordered, with exact GKV selection. Request keys are sorted in a private copy; duplicates and ambiguous rows fail. A zero-key request is unsupported even though real files may contain zero-key rows. GKV alias expansion and multi-file/delta overrides are outside this API.
- POOL object extents, SG topology, driver properties and SGIT module/processor maps are checked. SPF module declarations must agree with SGIT. Stored 12-byte SPF parameter headers become 16-byte APM headers with zero error codes and eight-byte payload padding. Known nested APM configuration objects are bounded; unknown graph/property requirements are explicitly unsupported. DSP-specific calibration leaf bytes remain opaque bounded payloads, not a claim of acoustic validity.
- CSLU/CAKT/CDLU select initial CKVs. CDDE/CDDO counts must match and MIID/PID rows must be ordered and refer to declared modules. Default rows are collected first, applicable specific rows decrement per-MIID remaining parameter counts, then remaining defaults are emitted in upstream order. This reproduces the actual upstream reference-count semantics, including their distinction from per-PID replacement. A partially supplied module CKV is explicitly rejected: the pinned upstream initial-query path can otherwise search stale global-buffer values. A requested CKV key not consumed by any selected table, or an absent requested value, also fails instead of silently falling back.
- Persistent/offloaded selected parameters, nonempty AMDB/boot, global-persistence, driver-calibration or hardware-offload maps, non-ADSP routing, unsupported endpoints and external subgraph dependencies prevent all packet output. Global map checks are deliberately conservative and may reject a file even if its additional feature belongs to another graph. The typed result identifies this limited implementation scope; it does not label such files corrupt.
- Real SPF module-connection records can refer to optional external modules (for example an echo-reference path), while their selected subgraph topology is closed. Those source records are retained verbatim and remain visible in GRAPH_OPEN. An offline plan makes no assertion that such external modules are already open; C1b/hardware qualification must resolve their actual firmware behavior. Explicit external **subgraph** destinations are rejected by this standalone initial-plan API.

## Actual source and license

The implementation was written against these pinned primary sources. Qualcomm's BSD-3-Clause notice is preserved in `LICENSE`.

- [AudioReach graph services 3094583c726710b66eb0204fc5d6a7b336d9e575](https://github.com/AudioReach/audioreach-graphservices/tree/3094583c726710b66eb0204fc5d6a7b336d9e575): `acdb/src/acdb_command.c` (`BuildSubgraphDataRsp`, `BuildSpfPropertyBlob`, subgraph connections, initial calibration and tagged modules), `acdb/src/acdb_data_proc.c` (GKVT/GKVL, persistence and offloaded properties), and `spf/api/apm` (command/property/module/connection formats).
- [AGM e9165150db2442f03e202496e8484ec662862ff8](https://github.com/AudioReach/audioreach-graphmgr/tree/e9165150db2442f03e202496e8484ec662862ff8): `service/src/graph_module.c` constructs codec-DMA interface and hardware-endpoint media SET_CFG data. Media config is `{u32 rate,u16 width,u16 channels,u32 format}`.
- [Configuration d9b13696adc1e0fd34a6ce8ef383763a981574b9](https://github.com/AudioReach/audioreach-conf/tree/d9b13696adc1e0fd34a6ce8ef383763a981574b9): all 16 genuine fixtures are pinned by SHA256 in `Tests/Fixtures/AcdbCr/inventory.json`; public semantic keys are in `qcom/kvh2xml.h`. No opaque vendor calibration format was invented and no synthetic mutation is presented as a vendor fixture.

`Tests/AudioCal/upstream_oracle.py` builds all 12 unchanged upstream ACDB C files and the real Linux file/heap/mutex/log/memory/string implementations. Its only portability adaptations are a compile-time `__unused` attribute and upstream's SYSLOG branch. Public ACDB APIs produce the comparison bytes; lookup/calibration functions are never stubbed. `generate_vectors.py` enumerates real file keys and invokes that oracle, recording all source/fixture/result hashes. The upstream oracle is used only on genuine inputs; malformed-input sanitizer tests run the bounded production compiler.

`Tests/run_audio_cal_tests.py --output PATH` generates and tests all 16 fixtures under native/NT ASan+UBSan, checks the executable consumer, and records retained-source hashes. `Tests/check_audio_cal_arm64.py` builds actual EFI ARM64 and WDK ARM64 objects. These checks qualify offline file/wire behavior only. No active audio driver or hardware binding is included in this increment.
