UsbDpPhyCrLib contains the SM8450 HDK QMP USB3/DP, SNPS HS and FSA4480 policy. UsbDpPhyCrDxe is its native dependency adapter and retains the existing EFI protocol and MDSS handoff ABI. The core never owns controller DMA or claims that a PHY readiness flag proves controller retirement.

The provider supplies separately assigned translated QMP/HS views, checked IO and actual provider lifetime health, qualified reset/clock/rail owner callbacks, and FSA4480 standard-mode SPB. The core keeps four clock and six rail journals, two exact consumer identities, the confirmed route and reverse cleanup. A failed dispatched write retains ownership. A local bus-frequency failure owns no switch write. Positive incomplete statuses never publish readiness. A malformed successful clock/rail acquisition without an ownership output retains its uncertain private token with NOT_READY. It can only be retired through the same private provider owner, whose off operation must be idempotent and exclude foreign owners.

Register tables retain GPL-2.0-only attribution from [Linux qcom QMP combo](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/drivers/phy/qualcomm/phy-qcom-qmp-combo.c): sm8350_usb3dpphy_cfg also serves SM8450. Reset deassertion precedes AUX/PIPE clock preparation. [Linux HDK supplies](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/arch/arm64/boot/dts/qcom/sm8450-hdk.dts) qualify the two QMP and three HS regulators. HS override e6/0c/17 comes from [Android waipio-qrd](https://github.com/OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8450/blob/877203a7cf9b79973d44a9db716490f95d820110/kernel_platform/qcom/proprietary/devicetree/qcom/waipio-qrd.dtsi), included by the HDK board. SBU switching follows [Linux fsa4480](https://github.com/torvalds/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/drivers/usb/typec/mux/fsa4480.c).

Validation uses actual native and NT core builds with ASan/UBSan, every dispatched startup/DP/release callback fault, partial provider ownership, foreign clients, route conflicts, deadlines, checked tuning and one-way freeze. A freeze delivered from each startup callback prevents all subsequent callback dispatch and retains the exact partial journals. Sixty-four nominal states compare final register images across the saved pre-extraction native driver, the new native adapter, and both shared-core ABIs. The native participant tests retain raw error/status, rail/clock, route and readiness/touched-mask coverage. Real ARM64 EFI core/adapters and WDK core objects are separately compiled; those tests do not establish physical Windows ownership or device bring-up.

Windows composition requires one permanent shared provider, rather than independent USB and DP mappings. It must own the assigned QMP and HS aliases, actual PEP hardware/D0 lease, referenced clock-control/absolute-clock-owner/rail-owner endpoints, and an assigned ResourceHub SPB connection to FSA4480@0x42. The clock callback verifies the acknowledged nonpending private vote; reset access requires the same exclusive native-to-Windows writer transfer. Acquire uses an observed current Type-C route from the existing single GLink/UCSI producer. A typed USB/DP lease retains its provider and dependencies through every failure; a live DP client forbids route mutation or removal of the common bank by USB. Role-child/controller stop and native USB writer retirement are independent evidence supplied by the URS parent before USB release. No current ACPI PHY assignment, physical transfer producer, ResourceHub FSA connection, or Windows provider publication is created by this extraction. Those are concrete integration work, not readiness inferred from the core's metadata.
