# SoundWireCrLib

This portable engine initializes the SM8450 SoundWire v1.7 EE1 controller, enumerates expected HDK8450 slaves and performs asynchronous byte register reads/writes. It is an unreferenced library with no active PEP, ACPI, MMIO mapping or Windows endpoint. The real platform resource adapter is still required before it can touch hardware.

The engine uses the actual OSKAL interrupt API and atomic event operations. Its MMIO, reset, shared-resource lease and deferred-work interfaces contain no default-ready implementation. It requires an observed v1.7 hardware version, nonzero FIFO depths, enough enumerator slots, an inactive/empty EE1 controller and an actual retained 9.6 MHz bus clock. An unexpected existing owner is rejected before reset or controller writes. The v1.7 CPU1 registers differ from older controllers; a version mismatch is not silently treated as compatible.

`Start` acquires the exact resource lease, asserts owned slave reset, programs frame/enumerator/EE/interrupt/controller setup, and schedules the bounded link check. `Step` advances it to BusReady. The board owner starts both WCD RX/TX controllers before `ReleaseSlaves` releases their shared reset; a pre-effect BUSY may be retried. WCD observes the post-reset 20 us hold and WSA the required 5 ms enumeration interval. Expected immutable device IDs are matched against actual enumerator registers and attached/alert status. Each returned logical address is bound to the controller, reset epoch and enumeration serial. An enumeration-change event invalidates the old binding even if a detach/re-attach restores the same ID and logical address; any outstanding request remains quarantined until real quiesce.

There is one outstanding caller-owned register request. A request is journaled before the command MMIO write. The engine checks FIFO limits, uses the source-defined 100 us pre-read and 250 us post-read delays, matches the actual read command ID, and requires an empty FIFO before allowing command-ID reuse. Wrong IDs, overflow, timeout, unexpected reset, removal and failed accesses quarantine the core; it does not flush and report success. Sequence and epoch counters never wrap. Ordinary writes provide no slave ACK, so the result is explicitly `CrSwWriteDrained`; a caller must read back any register value it needs to confirm. The engine never treats that write result as proven PA mute or codec programming.

The OSKAL callback only reads/acknowledges owned controller status, publishes atomic events and schedules work. Worker APIs are externally serialized, and scheduling cannot synchronously reenter them. Bus/fault events are interrupt-driven. No ordinary read-result-ready interrupt exists in the Android v1.7 mask, so short scheduled FIFO checks occur only during explicit startup or an outstanding register request. Idle controllers do not poll. A final status capture before sending or returning a result detects a fault latched before OS interrupt callback delivery. Codec in-band pending IRQ stays masked until a real WCD/WSA nested interrupt owner is implemented; this increment provides identification/register access, not MBHC or live codec interrupt service.

`Stop` closes capture admission, masks the owned interrupt source, unregisters/drains OSKAL, cancels/drains deferred callbacks, then calls the real resource owner's exact-lease `Quiesce` before release. Unknown requests remain retained until this physical quiesce completes. Shared WCD quiesce returns BUSY until both RX/TX cores have closed admission and drained callbacks: stop the other core and retry the first. A failed mask does not justify unmapping; independent IRQ rundown and the provider's actual reset path remain required. A malformed acquire result or release failure that erased its lease is pinned as uncertain, with no public forget/reset shortcut. The adapter must retain context, callback code and native synchronization storage throughout all partial failures.

## Actual consumer composition

The next AudioCr endpoint adapter must own one coordinated HDK audio resource group, alongside its existing typed ADSP facade reference. It must provide:

1. Exact LPASS controller windows and real core IRQ resources for RX 0x3210000/SPI 155, TX 0x33b0000/SPI 496 and WSA 0x3250000/SPI 170. TX wake SPI 520 is inventory only; this engine does not enter clock-stop/wake mode. Bind OSKAL's real native/KMDF/WDM backend; the core does not manufacture resource descriptors.
2. Shared PEP PRM/hardware/clock votes and LPI pins, with the actual live bus frequency. Acquire must reject an existing unowned controller rather than commandeer it. Every MMIO callback admits the exact current lease through the access, and software resets/power loss close all affected admissions before changing hardware. No direct-clock fallback or additional ADSP restart/owner exists here.
3. The real S10B/BOB and reset/shutdown owner: WCD TLMM 43 shared across RX/TX, WSA TLMM 1/89. The provider coordinates shared reset and holds low at least 20 us before returning from Assert. Its Quiesce retires actual old bus effects; elapsed time, local counters or a simulator Boolean are not a production receipt.
4. A serialized worker, IRQ-safe bounded schedule operation, timer/deferred rundown, and a permanent-enough context/code anchor that survives PnP stop/remove until exact Stop succeeds. OSKAL interrupt configuration stays immutable while owned. `Schedule` failure must still be handled by an already-retained worker/teardown path.

The concrete first consumer starts RX/TX, releases shared reset, obtains both IDs, then reads WCD's CHIP_ID0 and efuse variant through the TX slave. Android creates the WCD register map on TX; RX is enumeration-only in the target inventory. For WSA it enumerates both IDs, reads CHIP_ID0/OTP, reads PA_FSM_CTL and, if necessary, clears only bit0 then reads it back. A mismatch means identification/mute qualification failed. `SoundWireCrTest.c::ProbeConsumer` executes this flow against the actual engine and the documented register model, including a deliberately ineffective write that must not be mistaken for confirmed programming.

This does not activate a stream. Port-bank switching, macro mixers, codec IRQ/MBHC, PRM protocol integration, graph/media configuration, SMMU/DMA ownership and matching HDK calibration/protection remain separate required work. Public QCM6490 calibration cannot authorize HDK speaker unmute. No WaveRT endpoint should be published from successful chip-ID reads alone.

## Source and validation

The controller sequence and register layout are source-qualified against OnePlus Android modules commit `877203a7cf9b79973d44a9db716490f95d820110`, under `vendor/qcom/opensource/audio-kernel`:

- `soc/swr-mstr-registers.h` and `soc/swr-mstr-ctrl.c`: v1.7 CPU1 FIFO/IRQ layout, EE1, frame setup, FIFO fields, command packing, timings and enumeration.
- `asoc/codecs/wcd938x/{wcd938x.c,wcd938x-slave.c,wcd938x-registers.h}`: actual reset timings, RX/TX binding and TX register-map owner.
- `asoc/codecs/wsa883x/{wsa883x.c,wsa883x-registers.h}`: 5 ms enumeration wait, chip/OTP identification and PA-control addresses.

Android audio DT `252b88fe37d30b9dadc63a86392833c731867fbb`, `waipio-audio-hdk.dtsi` and parent overlay, supplies the HDK controller/slave identity. Mainline `a53261b60834ce617cc4f3c7723dda8285c59789`, `drivers/soundwire/qcom.c`, independently confirms that ordinary writes have no returned slave status and that read IDs/FIFO state must be checked. Source-derived control sequencing is licensed GPL-2.0-only; upstream attribution and the complete license are retained in LICENSE. No upstream implementation is included by `#include .c`.

Run `python3 Platforms/CranePkg/Tests/run_soundwire_tests.py --output .tmp/soundwire-tests`. Tests compile the actual engine with the pinned original register headers (only conflicting unrelated codec access-enum names are namespaced). They cover coordinated WCD reset, WCD/WSA ID reads, PA-off readback, multiple command-ID cycles, source-layout/version/FIFO qualification, stale bindings, reset/fault ISR inside a submitted write, an undelivered hardware fault latch, unknown MMIO effects, partial OSKAL registration, retained cleanup, malformed lease providers and counter exhaustion. Native and NT modes use ASan+UBSan. The hardware model supplies explicit successful resource/reset evidence only for tests; it is not linked into production.

`check_soundwire_arm64.py` compiles both core and target against actual EFI and ARM64 WDK/KMDF headers. These are compilation and composed protocol/state-machine results. Real interrupt delivery, rail voltages, hardware enumeration and playback still require device testing with the real resource adapter.
