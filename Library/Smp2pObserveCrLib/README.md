# Read-only SM8450 ADSP SMP2P observer

This independently written MIT library observes the published SMP2P v1 format in ADSP SMEM host 2, inbound item 443. It has no allocator, provider discovery, interrupt registration, outbound item 429 access, acknowledgement, SEND operation or processor restart operation. PIL remains the outbound master-kernel writer and physical loader/retirement mechanism.

The caller retains its actual SMEM access and supplies a fixed `Probe`, aligned `Read32`, and target memory-ordering `Fence` boundary. `Probe` may report a missing item before ADSP starts; the source stays attached while a later bounded startup retry discovers it. The source's increasing access incarnation is caller-owned bookkeeping, not an SMEM generation or boot identity. An item address is compared for observed relocation, never used as reboot or authentication evidence.

Capture reads two bounded copies with header bracketing, up to 180 word reads. The v1 header is 20 bytes followed by at most sixteen 20-byte entries (340 bytes total). Validation checks extent, aligned address, magic, revision, sending PID 2 / receiving PID 0, total/valid bounds and exactly one 16-byte `slave-kernel` name including its trailing zero bytes. It preserves raw header fields, flags, selected entry and value. Different headers, views or table samples are transient; stable unsupported/malformed data is explicit. Two matching reads do not prove atomicity or exclude changes that occur and revert entirely between reads. The native IRQ sequence fence remains necessary.

The source owns the exact latest capture receipt. Journal `Record` rejects copied, modified, previously consumed or stale-event snapshots. A successful `Record` means the diagnostic was recorded, including missing, transient or fault diagnostics; it does not mean READY. Consult `Observe` for `Pending`, `Stable`, `Bound`, `FreshAfterBind`, `ReadyObserved` and sticky fault reasons. `SourceLost` stops further provider callbacks for that attachment.

Initialize source and journal once in permanent unmoved storage. Attach with the actual retained access; arm an exact lease before `LoadAndStart`, carrying the actual controller/start-action IDs and pending RX event sequence. Record pre-load observations. Bind only the image/binding/boot IDs returned by the actual loader. Binding keeps previous faults and forces a new capture: a pre-bind snapshot cannot clear post-bind pending state. A fresh stable sample whose READY bit is zero is still not ready. Transient or expected pre-load missing data must not complete/rearm the pending interrupt. A stable valid sample can be consumed only together with the adapter's exact event fence.

Fatal, observed READY withdrawal, qualified restart flag transition, stable header/entry identity changes, post-bind missing state, malformed/unsupported data and provider/read failures remain sticky for the arm. Ordinary READY, handover and stop-ack carry no authentication, old-instance graph/DMA retirement or automatic recovery authority. An explicit close only detaches this local observer after the caller has drained callbacks and work. Retain native/provider ownership separately if any external teardown is uncertain. Source reattachment and a new arm require increasing access/action identity; counters never wrap.

The bounded 16-entry journal keeps immutable event records until ring eviction, identified by a nonwrapping serial. `ReadEvent` explicitly returns `NOT_FOUND` for evicted records. New arms preserve serial/token and historical record counters. All operations and callbacks require caller-provided PASSIVE serialization; this library supplies no locking or IRQ concurrency primitive.

## Source references and attribution

Wire format facts and hardware routing were checked against these pinned public sources. The implementation does not copy their driver code. Their original notices are retained in the accompanying development reference snapshots:

- [Android `smp2p.c`, commit 449760504b3a75728eb60479f5b34dc51cb263ce](https://github.com/OnePlusOSS/android_kernel_oneplus_sm8450/blob/449760504b3a75728eb60479f5b34dc51cb263ce/drivers/soc/qcom/smp2p.c): GPL-2.0-only; copyright Sony Mobile Communications AB (2015) and The Linux Foundation (2012–2013, 2018–2019). Supplies the published table layout and single-writer model.
- [Android `qcom_q6v5.c`, same commit](https://github.com/OnePlusOSS/android_kernel_oneplus_sm8450/blob/449760504b3a75728eb60479f5b34dc51cb263ce/drivers/remoteproc/qcom_q6v5.c): its original SPDX tag is `GPL-2.0`. Qualifies fatal/ready/handover/stop-ack and distinguishes the separate watchdog path.
- [Android waipio SMP2P device tree, commit 877203a7cf9b79973d44a9db716490f95d820110](https://github.com/OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8450/blob/877203a7cf9b79973d44a9db716490f95d820110/kernel_platform/qcom/proprietary/devicetree/qcom/waipio-smp2p.dtsi): no per-file SPDX header is present in the pinned file. Supplies host 2, items 443/429, LPASS client 3 signal 2 and the exact inbound entry name.
- [Linux SM8450 device tree, commit a53261b60834ce617cc4f3c7723dda8285c59789](https://github.com/sunflower2333/linux/blob/a53261b60834ce617cc4f3c7723dda8285c59789/arch/arm64/boot/dts/qcom/sm8450.dtsi): BSD-3-Clause. Independently confirms SM8450 routing and ADSP bit assignments.

Host tests exercise the actual library with EFI headers and an NT API type fixture under ASan/UBSan. They model only the retained SMEM read boundary. Actual SMEM provider lifetime, shared RX delivery, Subsystem admission, native WDK composition and hardware behavior require the integrating driver's separate tests.
