# Native display startup and console binding

When replacing pre-boot scanout on SM8250/SM8350, acquire the access/rail and positive interconnect prerequisites, then hold the selected output reset low before pulsing the MDSS core BCR, retiring inherited functional clocks, or withdrawing the two private display interconnect demands. Keep the existing shared supplies enabled. This blanks the output through its qualified GPIO owner; it does not claim all panel bias rails are switched off.

`MdpNativeResources` requires an output-blank callback. A failed acknowledgment retains the owner and prevents core retirement. The command frontend binds the panel reset GPIO low before the core reset; the video frontend acquires the resident bridge owner and holds its reset low. A successful early bridge acquisition is journaled separately from a partially owned failed acquisition, so reset retries cannot inadvertently demand reset high. LT9611 MCU IRQ work stays gated while reset is low or its write acknowledgment is uncertain.

Public ordering reference: OnePlusOSS/android_kernel_modules_and_devicetree_oneplus_sm8350 at `1e7b5673e7cc29d9af9fb0f58597055d07de6c6a`, `kernel/msm-5.4/techpack/display/msm/dsi/dsi_display.c`, `dsi_display_disable()` and `dsi_display_unprepare()`: panel disable/unprepare precedes host/link/PHY/core shutdown. The existing qualified target and panel descriptors provide the GPIO routes; no guessed bias-off or global fabric reset is introduced.

The Crane SimpleWindowManager override waits for the actual system-table input console and its SimpleTextInputEx protocol before stage-two initialization. ConSplitter installs the protocol before updating ConsoleInHandle, so protocol notifications alone are insufficient: the initialization event also retries every 100 ms and closes on success. The shared platform console selector accepts ConnectController NOT_FOUND only if subsequent real GOP/path resolution succeeds. Upstream MU returns NOT_FOUND when no additional driver starts on an already managed controller.

Validation covers actual resource retirement ordering, committed GPIO failures, retained owner/retry behavior, IRQ traffic while reset, delayed input console publication, existing GOP selection, and native output/power/EBS paths. These host and DEBUG image checks do not prove physical DSI/HDMI output. A GOP publication message is not a link or panel acceptance result. Confirm reset-before-core order, successful SWM initialization, preferred graphics console selection, and visible output in the next board test.
